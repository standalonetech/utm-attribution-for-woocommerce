# 1.3.2 — Noise cleanup Tools tab + Visits bulk delete

Status: approved 2026-10-02. Part 2 of 2; depends on [1.3.1-noise-filter-and-settings.md](1.3.1-noise-filter-and-settings.md) (classifier statics, settings, `ip_hash_visited` index).
wp-admin only, no WP-CLI. No schema change.

## Scope

1. `Utm_Attribution_Cleanup`: background Scan → CSV preview → Delete via Action Scheduler (bundled with WooCommerce).
2. **Settings → Tools** tab UI with progress bar.
3. Visits list "Delete" bulk action with the same protected-visit guard.
4. Dismissible upgrade notice linking to Tools.
5. Action `utm_attribution_visits_deleted`.

## State

- Option `utm_attribution_cleanup` (not autoloaded): `job` (id, mode scan|delete, status, user_id, from/to UTC, max_id, cursor, settings_hash, repeat anchor map, counts, top UAs, heartbeat), `last_scan`, `last_run` (finished_at UTC, user_id, deleted, protected).
- Option `utm_attribution_cleanup_lock` (not autoloaded) via atomic `add_option()`; stale after 10 min without heartbeat.
- Not transients: jobs run in cron with no current user and object caches may evict mid-job.
- User meta `utm_attribution_cleanup_notice_dismissed`.
- Action Scheduler hook `utm_attribution_cleanup_batch`, group `utm-attribution`, args `array( 'job' => id )`.

## Engine

Class loaded outside `is_admin()` (Action Scheduler runs in cron).

**Start** (`admin-post.php`, nonce + capability): acquire lock → snapshot `MAX(id)` → site-time range → UTC via `Utm_Attribution_Reports::utc_bounds()` (private → public) → `settings_hash` = md5 of effective compiled patterns + toggles + internal domains → store job → `as_enqueue_async_action()`.

**Batch** (keyset): `SELECT id, user_id, ip_hash, user_agent, landing_url, visited_at … WHERE id > cursor AND id <= max_id [AND visited_at range] ORDER BY id LIMIT n` (5000 scan / 1000 delete). Classify in PHP, first match wins:
1. `staff` — user_id set and `is_excluded_user()` (cached per user in job).
2. `monitor` / `bot` — `classify_user_agent()`; NULL UA = keep.
3. `non_page` — `is_noise_path( wp_parse_url( landing_url, PHP_URL_PATH ) )` (handles old rows with query strings).
4. `repeat` — ip_hash set, landing_url has no `utm_source=`, last *kept* row for `md5(ip_hash|ua|utm_source|utm_medium)` within 30 min (same key as the 1.3.1 live merge, source included). Kept rows become anchors; map pruned to last 30 min and stored in job. No window functions (MySQL 5.5.5+/MariaDB). Ascending id = ascending visited_at.

**Protected:** (a) `SELECT visit_id FROM conversions WHERE visit_id BETWEEN batch_min AND batch_max`; (b) open-order visit ids computed once at start: `wc_get_orders( pending, on-hold, checkout-draft, failed; paginate 200 )` + `$order->get_meta( '_utm_attribution_visit_id' )` (HPOS-safe). Matters because `get_top_metrics` INNER JOINs visits — orphaned conversions silently vanish from campaign tables.

**Scan** accumulates per-category found / protected / will_delete and top UAs (map capped 200 → top 10).

**Delete** re-classifies, then `DELETE … WHERE id IN (…) AND id NOT IN (SELECT visit_id FROM conversions WHERE visit_id IN (…))`, fires `utm_attribution_visits_deleted( $ids, 'cleanup' )`, queues next batch.

**Finish:** write `last_scan`/`last_run`, release lock, drop anchor map/top UAs of finished delete job. Idempotent (re-run deletes 0). Cancel unschedules group + marks cancelled; each batch checks job id and `running`.

**Delete allowed only** if `last_scan` is the current user's, < 30 min old, same range, same `settings_hash` — else "Settings or data changed — please scan again".

## Tools tab (`&tab=tools`)

- Optional From/To `<input type="date">`, labelled site timezone.
- **[Scan]** → progress bar polls `admin-ajax.php?action=utm_attribution_cleanup_status` every 3 s (nonce + cap, `wp_send_json_success`; polling also wakes Action Scheduler's async runner).
- Results table: Bots & crawlers / Uptime monitors / Non-page URLs / Repeat visits without cookies / Staff visits / Total × Found / Protected / Will delete; top 10 UAs (`esc_html`). Repeat shows "n/a (IP hashing off)" when applicable.
- **[Download rows to be deleted (CSV)]** → `?utm-export=noise` in `Utm_Attribution_Export::maybe_export()` (existing nonce + cap); streams 5000-row batches through `fputcsv` + existing `escape_csv_cell()`. Columns: ID, Category, Visited At (site time), Source, Medium, Campaign, Landing URL, Referrer, User Agent. Never ip_hash.
- **[Delete N visits]** disabled until "I understand this cannot be undone" ticked and a valid scan exists; backup hint shown.
- Progress persists across page loads; "You can leave this page"; after 2 min idle: "Waiting for background processing — see WooCommerce → Status → Scheduled Actions (group utm-attribution)"; **[Cancel]**.
- Last run: `wp_date`, user display name, deleted/protected.

## Visits bulk delete

- `cb` column, `column_cb()`, `get_bulk_actions()` → `delete`. Form stays GET; nonce `bulk-visits`.
- Handled on `load-{$visits_hook}` (hook suffix from `add_submenu_page` return): `check_admin_referer`, capability, `absint` ids (max 100), drop protected ids via `Utm_Attribution_Cleanup::get_protected_ids()`, same guarded DELETE, fire `utm_attribution_visits_deleted( $ids, 'bulk' )`, PRG redirect `deleted=N&skipped=M` → notice "N visits deleted. M skipped because they are linked to orders."
- `admin.js` `confirm()` before submit.

## Upgrade notice

Only on plugin screens and `plugins.php`, to users with the capability, when visits table non-empty, no `last_run`, not dismissed. Text: "UTM Attribution now filters more bot traffic. Review and remove past bot visits in **Settings → Tools**." Dismiss via nonce'd link on `admin_init` → user meta.

## Lifecycle

- Second deactivation hook → `Utm_Attribution_Cleanup::unschedule()` (also clears lock).
- `uninstall.php`: delete `utm_attribution_cleanup`, `utm_attribution_cleanup_lock`, user meta `utm_attribution_cleanup_notice_dismissed` (`delete_metadata( 'user', 0, …, '', true )`), `as_unschedule_all_actions( '', array(), 'utm-attribution' )` behind `function_exists`.
- Without WooCommerce: Tools shows "requires WooCommerce"; batches no-op.

## Edge cases

| Scenario | Handling |
|---|---|
| Settings/filters change between Scan and Delete | settings_hash + range + age check |
| Double click / two tabs | atomic lock + job id per batch |
| WP-cron disabled | admin-ajax polling triggers runner; 2-min message; Cancel |
| Deactivated mid-job | unschedule + clear lock |
| Real visitor's cookie points at a deleted visit | categories are non-human; bulk delete confirms; cookie→missing-row hardening deferred to 1.4 |
| Anonymised rows | NULL UA kept; path rule still applies |
| Huge table, shared host CSV | streamed; date range as workaround |
| Capability lowered to editors | editors can delete — documented in README |

## Invariants

A1 conversions untouched. A2 protected visits survive. A4 range via `utc_bounds()`, display `wp_date`. A5 no orphaned conversions. A6 `wc_get_orders` + `get_meta` only. A8 CSV columns of existing exports, slugs, cookie, tables unchanged.

## Acceptance checks

1. Baseline SQL: visits count, conversions count/sum, orphan count (`conversions LEFT JOIN visits … WHERE v.id IS NULL`).
2. Tools → Scan completes; Will delete ≈ SQL estimate (monitor ≈35.7k, bot ≈38k, non_page ≈7.6k, repeat ≤13.1k); CSV has UA + Referrer, `=` cells prefixed `'`, no ip_hash.
3. Delete disabled until checkbox; change a setting → "please scan again"; two tabs → "already running".
4. Delete survives leaving the page; `last_run` shown; re-scan → 0.
5. After: total = before − deleted; conversions count/sum identical; orphan count = baseline; every open-order meta value still in visits; dashboard conversions/revenue unchanged for a fixed range.
6. Bulk delete one ordinary + one conversion-linked visit → "1 deleted, 1 skipped".
7. Notice visible on plugin screens before first run, gone after dismiss, never on Posts.
8. `SELECT status, COUNT(*) FROM wp_actionscheduler_actions WHERE hook='utm_attribution_cleanup_batch' GROUP BY status`.
